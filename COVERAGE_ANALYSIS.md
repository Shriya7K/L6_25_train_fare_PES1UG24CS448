## 1. Introduction to Coverage Concepts

In software quality assurance and white-box testing, test coverage measures the extent to which the application's source code is executed during automated test runs. It provides quantitative metrics to assess test thoroughness, identify untested execution paths, and uncover dead or unreachable logic.

### 1.1 What is Code Coverage (Statement / Line Coverage)?
Statement Coverage (or Line Coverage) measures the percentage of executable statements or lines that have been executed at least once during a test run.

`Line Coverage = (Executed Statements / Total Executable Statements) * 100%`

- **Focus**: Verifying that each line of code is reached and executed without encountering uncaught exceptions or runtime errors.
- **Limitation**: Line coverage alone does not ensure that decision logic has been thoroughly tested. A line containing an `if` condition can achieve 100% line coverage by satisfying only the True outcome, completely leaving the implicit or explicit False alternative untested.

### 1.2 What is Branch Coverage (Decision Coverage)?
Branch Coverage evaluates whether each decision point (such as `if`, `elif`, `else`, ternary operators, and loop exit conditions) has evaluated to both True and False during testing.

`Branch Coverage = (Evaluated Branch Outcomes / Total Possible Branch Outcomes) * 100%`

- **Focus**: Ensuring that every possible control-flow branch is traversed, testing both positive and negative decision paths.
- **Benefit**: Exposes subtle defects in control logic, missed edge conditions, and missing fallback/boundary behaviors that statement coverage fails to catch.

### 1.3 Key Differences Between Line Coverage and Branch Coverage

| Attribute | Line / Statement Coverage | Branch / Decision Coverage |
| :--- | :--- | :--- |
| **Question Asked** | *"Did execution hit this line of code at least once?"* | *"Did every condition evaluate to all possible outcomes (True and False)?"* |
| **Sensitivity to Logic** | Blind to untaken logical branches when code flows through a single path. | Rigorously checks both taken and bypassed branches. |
| **False Sense of Security** | High (a test can achieve 100% line coverage while skipping half of the decision logic). | Low (requires explicit test cases for both positive and negative outcomes). |
| **Detection of Edge Cases**| May miss boundary values that toggle branches. | Requires boundary and alternate path testing to satisfy both branch directions. |

### 2.3 Baseline Branch Coverage & Metric Clarification
In the starter baseline report generated by `coverage run --branch -m pytest`, the output table for `train_fare.py` reported:
- **Total Statements**: 31
- **Missed Statements**: 17
- **Total Branches**: 22
- **Partial Branches (BrPart)**: 7
- **Reported Cover**: **40%**

#### Clarification of the 40% Metric:
It is essential to distinguish between **pure branch coverage** and the **combined metric** reported in Coverage.py's `Cover` column:
1. **Coverage.py Combined Metric (39.62% ≈ 40%)**:
   `Coverage.py Cover = ((Stmts - Miss) + (Branch - BrPart)) / (Stmts + Branch) * 100%`
   `Cover = ((31 - 17) + (22 - 7 - 8)) / (31 + 22) * 100% = (14 + 7) / 53 = 21 / 53 ≈ 39.62% -> 40%`
   Here, 14 statements were executed and 7 partial branch outcomes were taken out of a combined total of 53 code elements.

2. **Pure Branch Coverage (31.82%)**:
   `Pure Branch Coverage = (Branches Evaluated / Total Possible Branch Outcomes) * 100%`
   `Pure Branch Coverage = 7 / 22 ≈ 31.82%`
   Specifically, out of 22 possible binary outcomes across 11 decision points:
   - Only 7 branches were partially evaluated (i.e. only one branch outcome was followed).
   - 0 branches were fully evaluated (both True and False).
   - 15 branch outcomes were completely bypassed.

- **Untested Logic in Baseline**:
  - Validation exceptions (`ValueError` for unknown class and invalid distance).
  - Minimum fare floor clamping (< 50 INR).
  - Tatkal concession override (`is_tatkal = True`).
  - Infant (< 5) and Child (<= 12) concession brackets.
  - Senior citizen female (50%) vs male/other (40%) concession brackets.

## 3. Targeted Test Design & Improvements

To achieve >= 90% (and ultimately 100%) coverage for both metrics, two dedicated and independent test suites were implemented.

### 3.1 Code Coverage Suite (`CodeCoverageTest_PES1UG24CS448_train_fare.py`)
This test suite executes all 31 statements in `train_fare.py`:
1. **Valid Travel Classes**: Tests `"SL"`, `"3A"`, `"2A"`, and `"1A"` to cover all rate dictionary lookup statements.
2. **Minimum Fare Capping**: Tests distances resulting in fare < 50 to execute line 11 (`fare = 50`).
3. **Input Validation & Exceptions**:
   - Unknown travel classes (`"INVALID"`, `""`) to execute `raise ValueError("unknown class")`.
   - Non-positive distances (`0`, `-50`) to execute `raise ValueError("invalid distance")`.
4. **Concession Rules**:
   - `is_tatkal = True` to execute line 17 (`return 0`).
   - `age < 5` (infant) to execute line 19 (`return 100`).
   - `5 <= age <= 12` (child) to execute line 21 (`return 50`).
   - `age >= 60` with `gender == "F"` to execute lines 23-24 (`return 50`).
   - `age >= 60` with `gender == "M"` to execute line 25 (`return 40`).
   - `13 <= age < 60` (adult) to execute line 26 (`return 0`).
5. **Tatkal Charges**:
   - Sleeper class calculations (`fare // 10`).
   - AC class calculations (`fare * 3 // 10`).
   - Lower bound clamping (< 100 -> 100).
   - Upper bound clamping (> 400 -> 400).
   - In-range nominal charges.

### 3.2 Branch Coverage Suite (`BranchCoverageTest_PES1UG24CS448_train_fare.py`)
This suite maps out every conditional statement and tests both Boolean outcomes:

| Function | Condition | True Outcome Test | False Outcome Test |
| :--- | :--- | :--- | :--- |
| `base_fare` | `travel_class not in RATE_PER_KM` | Travel class `"NON_EXISTENT"` / `""` | Travel class `"SL"`, `"3A"`, `"2A"`, `"1A"` |
| `base_fare` | `distance_km <= 0` | Distance `0` and `-1` | Distance `80` (> 0) |
| `base_fare` | `fare < 50` | Distance `10` for `"SL"` (10 < 50 -> 50) | Distance `50` (50 = 50) and `51` (51 > 50) |
| `concession` | `is_tatkal` | `is_tatkal = True` (returns 0) | `is_tatkal = False` (proceeds to age checks) |
| `concession` | `age < 5` | Age `0`, `2`, `4` (< 5 -> 100) | Age 5 (>= 5, proceeds to next check) |
| `concession` | `age <= 12` | Age 5, 8, 12 (<= 12 -> 50) | Age 13 (> 12, proceeds to next check) |
| `concession` | `age >= 60` | Age 60, 75 (>= 60, checks gender) | Age 13, 35, 59 (< 60 -> 0) |
| `concession` | `gender == "F"` | Gender `"F"` (-> 50) | Gender `"M"`, `"Other"`, `""` (-> 40) |
| `tatkal_charge` | `travel_class == "SL"` | Class `"SL"` (computes 10%) | Class `"3A"`, `"2A"`, `"1A"` (computes 30%) |
